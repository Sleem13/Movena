# Movena replacement

This directory is the cutover ledger for the approved whole-product rebuild.
The existing `frontend`, `mobile`, and `backend` remain the supported product until
their replacements pass the gates below. A new scaffold is not feature parity.

## Target ownership

| Domain | Replacement | Current authoritative writer | Removal gate |
|---|---|---|---|
| Identity | Django identity | Legacy API | Credential migration, revocation and permission tests |
| Care | Django care | Legacy API | Invitations, plans, responses and relationship isolation |
| Analysis | Python engine / Django jobs | Legacy API | Upload lifecycle, owner isolation and model promotion |
| Coaching | Django coaching | Legacy API | Goals, check-ins, escalations and reviewed decision support |
| Scheduling | Django scheduling | Legacy API | Availability, booking, joining and cancellation |
| Commerce | Django commerce | Legacy API | Idempotency, callback verification, orders and refunds |
| Notifications | Django notifications | Legacy API | Delivery, preferences, read state and retries |
| Administration | Django administration | Legacy API | Full role/capability matrix and audit trail |

`baseline.json` is generated by `scripts/rebuild_inventory.py`, without importing
the legacy app or triggering its startup database mutations. It includes
conditionally mounted routes; it is not a claim that every endpoint is deployed.

## Design

`design/role-workspaces.png` is the initial built-in Image Gen concept. Its sample
people and dates are illustrative only. Real screens must render backend records;
no sample patient data is seeded into connected environments. Use white surfaces,
blue actions, teal progress, and navy text, with coordinated dark and Arabic RTL
variants. Patient: Today / Progress / Care / Account. Therapist: Patients / Review /
Schedule / Account. Administrator: Overview / People / Operations / Account.
Preserve restricted admin/support capabilities even when they share a shell.

## Cutover gates

1. Contract and workflow tests pass for the domain on both clients.
2. Data-copy migration and restore rehearsals preserve IDs and relationships.
3. Only one service writes each domain; compatibility calls go to that owner.
4. Native device tests and web visual/accessibility tests pass.
5. Rollback is rehearsed, and sensitive data is absent from operational logs.
6. Remove old code only after its supported callers migrate. Keep required
   migrations, historical engine identifiers and evaluation evidence.

## Model gate

The checked-in baseline reports zero manually evaluated repetition videos.
New task models cannot be promoted without reviewed labels, participant-separated
splits and paired benchmark results. Existing hardware/data only; no paid training
or labeling is assumed. An unavailable metric is never a passing metric.

## Completion evidence

Record actual commands, outcomes, limitations and remaining work in `STATUS.md`.
Never mark a feature complete because its route, shell or adapter exists.
