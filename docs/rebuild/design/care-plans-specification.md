# Care-plan authoring journey

From Patients or Review, open the selected patient's Plans workspace. Show active,
paused and completed versions with author and dates. A plan expands to its exact
exercise instructions, dosage, weekdays, media/analysis requests and optional
targets. Never turn an unavailable target into zero.

Create a plan using a title, optional notes/date range and 1–20 ordered exercises.
Each exercise supports the full existing contract: sets, reps, days per week,
instructions, duration, rest interval, tempo, precautions, ROM/score targets,
explicit weekdays, media upload and AI analysis requirements. Advanced fields
remain grouped within the exercise. Values are clinician-entered, never generated
as treatment recommendations. Required dosage starts empty.

Publishing creates a new version and pauses that author's prior active plans.
Explain this before the primary Publish action. Keep history and old response
references. Pause/resume/complete use the existing author/administrator checks.
Clients retain a stable creation key across retries; the bridge reserves before
dispatch and refuses duplicate dispatch after uncertain outcomes. Recheck patient
access before serving a creation receipt. An unresolved response requires server
reconciliation; show that state without creating another version automatically.

Loading, empty, denied, offline, validation and saved states share recovery
components. Forms scroll on phones and under enlarged Arabic text. Use labeled
controls and 48-pixel actions. Never persist patient plan drafts in browser storage.
